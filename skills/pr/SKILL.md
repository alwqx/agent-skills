# 提交并创建 PR

将当前任务已完成的改动整理为一次清晰的提交，推送功能分支并创建 PR。遵循当前 agent 适用的仓库说明（AGENTS.md、CLAUDE.md 等）、提交格式、CHANGELOG 和 PR 模板要求。

## 语言要求

- Commit message 的标题和正文均使用英文，保留仓库要求的类型、scope 等格式，例如 `feat(desktop): add candlestick history with volume`。
- 本次新增或修改的 CHANGELOG 条目使用英文，保留现有版本标题、编号列表等结构；不为统一语言而翻译无关的历史条目。
- 以上是用户明确指定的语言偏好；即使仓库旧说明或历史记录使用中文，commit message 与本次 CHANGELOG 条目仍使用英文。用户后续有新的明确要求时以新要求为准。
- 会话或系统提示给出 commit / PR 署名行时，按其要求原样附加在末尾；署名行不受上述语言要求影响。

## 工作流程

1. 检查 `git status --short`、当前分支、远端以及暂存和未暂存差异，确认本次任务的文件范围。保留其他未完成工作，不将无关文件或秘密纳入提交。
2. 在 `main`、`master` 或仓库默认分支上时，先创建并切换到描述本次改动的功能分支；禁止直接在默认分支提交或推送。已有本次任务的功能分支时继续使用。
3. 完成仓库要求的文档更新，并用英文编写本次 CHANGELOG 条目，执行与改动相关的必要检查；本轮已经通过且之后没有相关代码变化的检查可复用结果。修复阻塞提交的问题，无法完成的验证在 PR 中如实说明。
4. 按实际文件范围暂存改动，复核暂存差异与当前分支，再创建一个用英文描述最终改动的 commit（标题和正文均为英文）。已有提交时不要为凑流程创建空提交，也不要擅自 amend 他人的提交。
5. 推送功能分支，首次推送用 `git push -u <remote> <branch>`。使用仓库实际远端，不默认强制推送。
6. 检查该分支是否已有打开的 PR；已有时复用并根据最终改动更新必要内容，否则用 `gh pr create --base <base> --head <branch>` 创建。PR 描述说明具体问题、最终行为、验证结果及重要限制，避免重复对话历史。使用结构化正文参数，或将实际多行正文写入临时文件并通过 `--body-file` 传入。
7. 确认 PR 创建成功，返回链接、提交短 SHA 和分支，并说明是否仍有未提交改动。创建 PR 后结束，合并由用户或既有明确授权的后续流程处理。

## 执行边界

- 用户明确请求提交、推送和创建 PR 后，在既有授权范围内连续完成；不因流程本身重复询问。工具要求的权限审批仍须遵守。
- 仅发现或安装此技能，不表示用户要求为当前工作区创建 PR。若用户只要求 commit，不自动扩展为 push 或创建 PR。
- GitHub 登录、网络或权限失败时检查具体原因；环境限制按工具规则请求授权。无法继续时说明已完成步骤与阻塞原因，不绕过权限限制。
